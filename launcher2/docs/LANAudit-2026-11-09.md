# Move or Die / ZeroTier: verificación del anfitrión

El anfitrión informó que una amiga migrada de Coco 1 no encontraba su partida LAN en Coco 2. Se continuó el trabajo de preparación de Windows pendiente y se publicó Coco 2 **0.6.46**. La conectividad entre los dos equipos no se ha vuelto a probar en esta sesión.

## Estado observado antes

- Red Coco unida y autorizada, estado local `OK`, dirección del anfitrión `10.77.37.1/24`.
- Controlador privado, `enableBroadcast=true`, límite multicast 32 y MTU 2800. No se modificaron estas opciones.
- Adaptador Coco IPv4 con métrica automática 35 y perfil Público; Ethernet 25, Wi-Fi 35 y Tailscale 5. La preferencia de interfaz puede afectar buscadores LAN que se vinculan al adaptador preferido; no se capturaron paquetes para atribuir definitivamente el fallo del juego a esa causa.
- Reglas de entrada para el `Love\win\love.exe` de Move or Die presentes tanto en la ubicación heredada como en la de Coco 2, para perfiles Privado/Público. No se desactivó el firewall.
- El registro de permisos tenía una espera de Defender hasta `1794727728`. El código previo aplicaba esa misma espera a una nueva reparación de red, por lo que podía omitirla durante días.

## Corrección y comprobación

La preparación al abrir Coco comprueba también adaptadores heredados de Coco 1. Selecciona únicamente la red Coco por nombre o dirección asignada, fija métrica IPv4 1 con selección automática desactivada y perfil Privado. No modifica otras redes ZeroTier, VPN o IPv6. Los errores de permisos se registran, sin anunciar éxito. Defender y red tienen esperas de reintento independientes; no se elimina la decisión anterior sobre Defender.

Pruebas: **9/9** de preparación Windows, incluyendo ejecución PowerShell con adaptadores simulados (Coco renombrado, otra red ZeroTier y Ethernet), errores de permisos y conservación del cooldown de Defender. Suite Rust completa **299 PASS, 0 FAIL, 7 opt-in ignoradas**. Preflight Node **531 PASS, 0 FAIL, 31 SKIP**; TypeScript/Vite y verificaciones del instalador/firma aprobadas por el builder. `git diff --check` sin errores.

Candidato publicado: Setup **20.836.394 bytes**, SHA-256 `42be4faff42d7c4dee72766b871296b7751af4d23669277a621607e720883629`, versión **0.6.46**. Publisher verificó el feed y descargó/comparó tanto el Setup versionado como el enlace fijo. Latest de Coco 1 sigue `v0.5.186`.

Después de instalar y abrir 0.6.46 en el anfitrión se observó: **ZeroTier métrica 1, automática Disabled, perfil Private**. Ethernet 25, Wi-Fi 35 y Tailscale 5 permanecieron iguales. El log confirmó `zerotier:lan`; `networkRetryAfter=0` y la espera anterior de Defender se conservó. Defender no está disponible en este Windows; esto no impidió aplicar la reparación de red.

Pendiente: la amiga debe recibir la actualización, permitir la preparación cuando Windows la solicite y reabrir Move or Die; ambos equipos deben recrear/buscar una sesión LAN. Ver [operación y diagnóstico](LAN.md). No se declara multijugador validado por pruebas locales del anfitrión.
